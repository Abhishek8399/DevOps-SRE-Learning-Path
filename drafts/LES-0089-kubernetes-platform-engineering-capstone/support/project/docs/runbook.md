# Platform operations runbook

## First five minutes

Name the failed user operation, tenant, start time, current Git revision and last change. Freeze competing reconciliation or rollout changes. Use the project kubeconfig explicitly. Preserve events, workload status, reconciler receipt and a user probe before restarting or deleting anything.

Run these read-only observations from the project root:

```bash
bash cluster/status.sh
kubectl --kubeconfig .state/kubeconfig get deployment,replicaset,pod,service,endpointslice -n team-a -o wide
kubectl --kubeconfig .state/kubeconfig get events -n team-a --sort-by=.metadata.creationTimestamp
kubectl --kubeconfig .state/kubeconfig describe deployment payments-api -n team-a
curl -v --max-time 3 http://127.0.0.1:18080/version
```

Do not start with `kubectl delete pod`. Deletion can be a safe controller test later, but it removes the failed instance and volatile clues before you know which layer owns the symptom.

## Symptom branches

### API unreachable

Confirm `.state/kubeconfig` exists, inspect its server address without printing client key data, and run `docker ps` for the three exact node names. A failure at API reachability means workload YAML has not yet been evaluated. Do not edit probes or Services.

### API says forbidden

Capture user, verb, resource, namespace and decision:

```bash
kubectl --kubeconfig .state/kubeconfig auth can-i create deployments \
  --as=system:serviceaccount:team-a:developer -n team-a
```

Inspect the namespace Role and RoleBinding. Do not grant cluster-admin to clear one denial. The denied secrets and cross-tenant tests are intentional invariants.

### API says invalid, policy or quota

Read the full status message. Owner/resource/security failures belong to CEL or Pod Security. “Exceeded quota” includes used, hard and requested capacity. Fix the request or negotiate tenant budget; deleting unrelated workloads without an owner is not remediation.

### Deployment accepted but not available

Follow Deployment → ReplicaSet → Pod → event. Pending suggests scheduling, quota after defaulting, taints, resources or topology. ImagePullBackOff is expected for the injected bad tag because the golden path uses `imagePullPolicy: Never`. Running but unready moves the investigation to probe paths, ports and application logs.

### Service has no endpoints

Compare Service selector with Pod labels and inspect EndpointSlices. A valid ClusterIP proves allocation, not backing endpoints. If endpoints exist, test from within the namespace before blaming the NodePort boundary.

### Drift returns

Read `.state/reconcile-receipt.json` and Kubernetes managed fields. Identify every writer. The teaching reconciler force-takes the fields generated by the platform. In production, two controllers fighting over replicas can turn every reconciliation into an outage; choose one owner or split fields deliberately.

## Recovery choices

- Reconcile: declared state is correct and actual state drifted.
- Rollback workload: a new Pod template cannot become ready and the prior ReplicaSet remains compatible.
- Roll forward: state/schema changed incompatibly or a small corrective release is safer.
- Reconstruct namespace: namespaced declarative state was lost; this does not restore application data.
- Restore etcd: control-plane state is lost or corrupt and an independently verified snapshot is authorized. This lab does not perform it.
- Recreate kind cluster: local cluster runtime is disposable. Preserve Git and receipts; do not describe this as an in-place production upgrade.

Recovery is complete only after the user operation, readiness, desired revision, policy health and observation window pass. Record what remains unknown.
