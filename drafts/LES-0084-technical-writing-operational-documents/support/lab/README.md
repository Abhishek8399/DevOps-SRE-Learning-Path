# LES-0084 guarded technical-document review lab

This offline lab reviews one fictional checkout-incident documentation packet. It performs no publishing, incident-room, provider, production, network, editor, ticket, email or messaging call. The facts, timestamps, procedures, documents and scores are teaching inputs, not organizational evidence.

Run from this directory in Ubuntu 24.04 as a normal user:

```bash
bash lab.sh doctor
bash lab.sh setup
bash lab.sh status
bash lab.sh roadmap
bash lab.sh claims
bash lab.sh timeline
bash lab.sh runbook
bash lab.sh freshness
bash lab.sh audiences
bash lab.sh evaluate material-claim-unsourced
bash lab.sh evaluate destructive-command-unbounded
bash verify.sh
```

The model has one defensible baseline and one isolated failure for each of 72 review gates. Five calculations expose claim-class conservation and attribution, timezone-normalized incident chronology, verifiable and mutation-safe runbook coverage, active-versus-archived freshness, and consistent audience views over one canonical fact set.

The guard refuses root, cloud/runtime/publishing authority, symlinks, wrong ownership and unknown artifacts. It creates one UID-scoped directory containing a sentinel and two copied fictional JSON fixtures. Cleanup removes only those exact files and proves the directory absent.

Independent practice requires reviewer-owned fictional or sanitized documents with hidden audience, safety, evidence and freshness changes. Never place employer incidents, customer data, credentials, tokens, contracts, vulnerabilities, private architecture, internal endpoints or confidential communications in this repository.
